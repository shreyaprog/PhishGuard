Cloud Security Impact

Phishing can expose passwords, MFA approvals, or active sessions. If an attacker gains access to a cloud identity, the impact depends on that identity's permissions and the customer's monitoring and response controls.

Potential impactComplementary defensive controls
Stolen cloud or email credentialsPhishing-resistant MFA where available, suspicious sign-in detection, password reset and session revocation.
Abuse of excessive IAM permissionsLeast privilege, role separation, short-lived credentials, periodic access review, and alerts for privilege changes.
Unauthorised console or API accessStrong authentication, session controls, CloudTrail audit logging, and rapid credential revocation.
Unauthorised cloud storage accessRestrictive bucket policies, block-public-access controls, encryption, access logging, and data monitoring.
Data exposure or account takeoverIncident response procedures, log review, credential rotation, access containment, and recovery planning.

AWS shared responsibility model

AWS is responsible for security of the cloud, including the physical facilities, hardware, networking, and virtualization layer. Customers are responsible for security in the cloud, including identity and access configuration, data, encryption choices, network rules, and workload settings. The exact division varies by AWS service.

Useful references: AWS Shared Responsibility Model, IAM best practices, AWS CloudTrail, and Amazon S3 security best practices.

PhishGuard analyses submitted URL text only. It does not connect to AWS or prevent cloud compromise; the controls above are complementary defensive measures.
